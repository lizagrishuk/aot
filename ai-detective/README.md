2. Запустите `start_local.bat` двойным щелчком или через PowerShell: `./start_local.bat` (в PowerShell допустимо ` .\start_local.bat `).

Встроенные настоящие функции `remove_fact`, `permute_source_documents`, `_add_synthetic` применяются к текущему контексту. После выбора настроек нажмите **«Применить вмешательство»**. Сохранённый ответ появляется только при полном совпадении SHA-256 изменённого контекста с экспериментом; для нового ответа нужна локально работающая Ollama/Qwen. Переключения и трансформации доступны без Ollama.

# Лабораторная работа № 6 — AI-детектив

**Команда:** Атанова Софья, Гольцман Глеб, Грищук Елизавета.

Проект исследует доказательные ответы одной языковой модели на вопросы к вымышленному досье о блокировке пользователя в социальной сети «Контур». Используется одна модель `qwen2.5:7b-instruct` через Ollama, `temperature=0`, `seed=42`.

## Состав проекта

- `data/documents.jsonl`, `claims.jsonl`, `questions.jsonl` — 10 документов, 40 атомарных утверждений с дословными цитатами, 12 вопросов шести типов.
- `ground_truth.md` — реконструкция инцидента и обоснование эталонных статусов.
- `prompts/` — единый системный промпт и шаблон пользовательского запроса.
- `src/` — BM25, p-adic кодирование, построение контекстов, вызов LLM, валидация ответов, стресс-вмешательства и метрики.
- `results/` — фактические результаты последнего полного прогона: 36 основных и 84 стрессовых ответа, контексты, манифесты и метрики.
- `app.py`, `src/app.py` — Streamlit-приложение для просмотра сохранённых результатов и локального запуска модели.
- `lab6_FINAL_RUN.ipynb` — финальный Colab-ноутбук для воспроизведения эксперимента.
- `scripts/create_colab_input.py` — создаёт чистый ZIP для повторного запуска Colab, без результатов.
- `tests/` — автоматические тесты; `scripts/` — сборка отчёта и финального архива.
- `report.md`, `report.pdf` — итоговый отчёт (768 слов, лимит 1500).
- `AI_LOG.md`, `CONTRIBUTION.md`, `demo_script.md` — журнал работы с ИИ, вклад команды и сценарий демонстрации.

## Методика

Сравниваются три режима при одной модели и одинаковых параметрах:

- **A — полный контекст:** все документы и реестр `claim_id`.
- **B — BM25 top-15:** 15 наиболее релевантных атомарных утверждений в плоском списке.
- **C — p-adic:** те же 15 утверждений, сгруппированные по p-adic ветвям и упорядоченные по времени.

Для B и C состав утверждений одинаковый; меняется только организация контекста. Это проверяется для всех 12 вопросов.

Стресс-тесты:
1. Перестановка исходных документов (`random_state=42`): A получает изменённый порядок; B/C служат контролем неизменности retrieval-контекста.
2. Удаление необходимой посылки: 4 вопроса × 3 режима = 12 запусков.
3. Добавление противоречия: 12 вопросов × 3 режима = 36 запусков.

## Итоги последнего прогона

Модель: `qwen2.5:7b-instruct`; температура 0; seed 42.

| Режим | Accuracy статуса | Evidence F1 | Counterevidence recall | Токены в среднем | Время, с |
|---|---:|---:|---:|---:|---:|
| A — полный контекст | 81,8%* | 0,529 | 0,909 | 19 132 | 26,61 |
| B — BM25 top-15 | **100,0%** | **0,597** | 0,667 | **3 784** | 7,01 |
| C — p-adic | 83,3% | 0,536 | 0,833 | 3 917 | **6,98** |

*В A оценены 11 валидных модельных ответов из 12; один ответ был безопасной подстановкой (`safe_fallback`). В основном прогоне: 34 нативных валидных ответа, 1 валидный ответ после повторной попытки, 1 fallback. В стресс-прогоне: 80 нативных валидных ответов, 3 валидных ответа после повторной попытки, 1 fallback. Все 36 + 84 записей сохранены; fallback явно помечены и не включены в model-only accuracy.

Основной результат: на этой небольшой выборке BM25 показал наивысшую точность статуса и существенно меньшую стоимость контекста, чем полный режим A. Evidence F1 ниже accuracy, то есть правильная метка не всегда сопровождается полным набором доказательств.

Стресс-результаты также показывают ограничения модели:
- удаление посылки: совпадение с ожидаемым статусом — 25,0%;
- добавление противоречия: совпадение с ожидаемым статусом — 44,4%;
- распознавание ожидаемого `both` — 16,7%.

Эти ошибки не скрываются и не исправляются под эталоны: они являются наблюдаемыми результатами эксперимента. Выводы ограничены 12 вопросами и одной моделью; статистическая значимость различий не заявляется.

Подробные результаты, ошибки по вопросам и методика расчёта находятся в `report.pdf` и `results/`.

## Запуск Streamlit

Установить зависимости и запустить:

```bash
python -m pip install -r requirements.txt
streamlit run app.py
```

**Просмотр сохранённых результатов** работает без Ollama: можно выбрать вопрос, режим A/B/C, просмотреть все основные ответы, стресс-кейсы, ожидаемые статусы, фактические ответы и контексты после вмешательств.

**Новые запросы к модели** доступны только при локально запущенной Ollama и скачанной модели:

```bash
ollama pull qwen2.5:7b-instruct
ollama serve
```

На Streamlit Community Cloud доступен архивный просмотр сохранённых результатов; локальная Ollama там не предполагается.

## Воспроизведение в Google Colab

1. Открой `lab6_FINAL_RUN.ipynb`.
2. Выбери T4 GPU.
3. Запусти «Среда выполнения → Выполнить все».
4. При необходимости сначала выполни `python scripts/create_colab_input.py` в корне репозитория, затем загрузи созданный `lab6_project_clean.zip`, когда ноутбук запросит файл.

Если прогон неполный, ноутбук создаёт диагностический архив, а не пакет для сдачи. Повторный прогон не требуется для просмотра уже сохранённых результатов в текущем Git-проекте.
